# 个人站 2.0 当前需求

本文件只记录现行行为。技术职责见[前端架构](frontend-architecture.md)，原型与技术选型的研究依据见[研究记录](research/frontend-architecture.md)和[内容导航研究](research/personal-site-content-navigation.md)。

## 目标与输入输出

- 以 `visual-atlas/personal` 原型的风格和 Bot 为起点，使用 Next.js App Router、React、TypeScript、Tailwind CSS 与 shadcn/ui 重建个人站，最终部署到 Vercel。无需沿用 Hugo / PaperMod 的页面与样式。
- 输入为个人资料、项目、既有 Markdown 文章、个人分身模型问答及原型 Bot 引擎；输出为首页、Projects / Notes / Thoughts 完整目录、站内文章正文及 About Me。
- 文章仍是网站内容。文章源仓库为 `Obisidian-Open`；本站只同步 `draft: false` 的文章，由源文件决定公开范围。
- 项目卡片维护本人角色与各自图标；有公开链接的项目可直接跳 GitHub 或官网，没有公开链接的项目只展示简介，不显示跳转箭头或链接悬停效果。笔记卡片展示标题和摘要并进入站内正文。首页回答与目录复用同一内容条目和卡片。

## 导航与首页

- 顶部菜单居左，依次为 Home、Projects、Notes、Thoughts、About Me，分别进入首页、完整目录或介绍页；GitHub 及主题切换始终居右。键盘顺序与视觉顺序一致。
- 首页保留个人介绍、Bot、四张主题卡片、输入框和累积会话。点击主题卡片或提交问题生成一次精简回答，可附多张独立的项目或文章卡片；顶部目录入口不触发问答。
- 主题卡片共用连续移动的关注底板，悬停与键盘聚焦轮转突出目标；触屏点击直接提问。卡片关注与输入框聚焦共用 Bot 的倾听状态，内部切换不重复点头。
- 同一标签页经目录、正文返回首页时保留会话；刷新或主动清空会重置。四个主题入口与自由问题统一调用模型，只回答作者、项目和公开文章相关问题；无关的通用问答应简短拒绝。未启用或失败时明确提示，完整目录仍可访问。
- 个人介绍与全部五个项目每次进入上下文。Notes / Thoughts 入口展示对应类型最新三篇，再从剩余文章随机取两篇，同次不重复，不足按实际数量；具体问题复用关键词检索，最多三篇、每篇 900 字符摘录。当前没有命中不能宣称作者从未写过。
- 页面保留完整会话，请求只发送上一轮成功问答和最近非空卡片列表（最多五条，保留顺序）。“第二篇”等确定性指代载入对应资料；歧义询问，不猜测。个人事实只由现有公开资料支持，不依据客户端历史补造经历。
- 从首页回答卡片进入文章时，正文页首返回对话并恢复会话滚动位置；从文章目录进入时返回该目录；直达或刷新后无会话时显示文章目录入口。正文页尾始终提供目录入口，文章 URL 的入口标记不影响公开正文或 canonical URL。
- 点击文章卡片时，选中的卡片与正文标题区做一次展开过渡；重复出现的同一文章只让实际点击的卡片参与。减少动态效果时直接显示正文。
- DeepSeek 关闭推理，使用真实流式 response，不显示 think，不模拟打字速度或逐张卡片等待。文字逐步可见，卡片在完整结构、引用和正常流终态均通过后一次显示。回答中禁止并发提交，输入框仍可起草；完成后即可追问，不等待 Bot 庆祝。
- 切换站内页面时请求继续，返回呈现实际进度或历史，不重播完成动作。清空取消浏览器和上游请求，迟到回调不恢复旧会话。流失败保留未完成文字与错误提示，无卡片，也不进入有效历史。滚动只在用户仍跟随底部时自动跟随，读屏只播报加载、最终回答及错误。

## Bot 与视觉

- 保留原型的暖色、字体和 Bot 气质；页面与交互允许重新布局。Bot 的眼睛始终限制在身体内，仅排除[首页](assets/bot-eyes/excluded-home.png)、[工作](assets/bot-eyes/excluded-working.png)、[生气](assets/bot-eyes/excluded-angry.png)样本对应的眼型 7、8，不删除其所属表情。
- 首次入场播放原引擎 `spawning`：粒子聚拢后身体从小形态展开。会话开始时同一个 Bot 移至 assistant 位置，清空时返回；过渡中可反向，减少动态效果时直接定位。
- 平静待机约 20～30 秒后随机播放开心、好奇、害羞、得意或俏皮的一种完整表情，约 2.5 秒后回到平静。无操作 60 秒进入持续休眠；再次操作以 `spawning` 粒子聚拢苏醒约 2 秒。休眠未完成就被打断时保持当前身体尺寸并显示聚拢粒子。回答可立即接管，后台不累计闲置时间。
- 点击 Bot 只弹跳，键盘 Enter / Space 可激活；无鼠标位置跟随、三击、拖动、长按或手动休眠手势。卡片或输入框关注时轻点头一次并保持安静倾听；正常回答固定书写，未匹配问题困惑，真正失败短暂警报。阅读正文返回开心或通知，切换主题惊讶。
- 正常回答展示完成后播放一次带彩带的转身、轻跳和落地粒子，再恢复待机或倾听；不显示进度环，不串联多种回答动作。场景按优先级裁决，不排队；回答抢占装饰动作。减少动态效果时保留内容与场景含义，停止装饰运动。
- `/dev/bot` 只在开发环境试播原引擎动作和尺寸，生产环境返回 404。素材来源与本站适配见[引擎说明](../src/components/bot/vendor/README.md)。

## 内容与技术边界

- 文章标题、类型、日期、摘要、slug、标签、草稿状态和正文只从 Markdown 原文读取。公开文章必须有完整元数据，slug 全局唯一并作为文章 ID；`categories` 是主题，`type` 决定 Notes / Thoughts。正文中的 Obsidian 双链按公开文章的源路径解析为站内链接，别名作为链接文字；目标未公开或不存在则构建失败，代码块不解析。首页文章列表和引用由回答模块选择并校验，客户端卡片只从同一公开目录解析。完整正文只在服务端读取。
- 页面与共享导航不管理 Bot 引擎细节；Bot 不判断问题内容；首页会话不读取文件系统。模块依赖按[架构文档](frontend-architecture.md)执行。
- 主题默认跟随系统，用户选择的明暗主题保存在 `localStorage`；会话只存内存。Bot 引擎仅在浏览器动态加载。
- GitHub Actions 每天从源仓库同步并校验公开文章，在同一任务中构建通过后才提交变更；Vercel Git 集成以 SimWeb `main` 的提交部署。公开页面继续预生成并静态提供；`/api/answer` 动态处理全部首页提问，每轮一次模型生成，无自动重试或预设回退。公开启用前须确认服务端密钥、两个公开入口限流和费用控制；快捷入口也消耗调用额度。

## 验证

运行 `npm run check`、`npm run format:check`，并在构建后运行 `npm run test:e2e`。重点覆盖桌面与小屏的目录、问答、阅读返回、刷新清空、主题与 Bot 的状态切换；视觉变化需在实际页面检查。
