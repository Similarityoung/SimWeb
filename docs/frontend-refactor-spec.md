## Bot 点击、完成动画与待机表情（2026-09-22，当前实施约定）

- Bot 专用手势只保留点击弹跳，立即响应；不维护连点大笑、拖动归位、长按或 Escape 休眠。按钮沿用浏览器原生点击，支持鼠标、触摸、Enter / Space，恢复正常触摸滚动。自动睡眠由页面闲置触发，与 Bot 专用手势分开。
- 正常回答的文字与卡片全部展示后，使用 celebrate 播放一轮约 2.4 秒的完成动画：带着彩带转一整圈约 700ms，轻跳一次约 500ms，落地后散出 14 个低速彩色粒子并自然消失；彩带随旋转产生，停转后自然收尾，落地粒子单独触发，随后恢复待机／倾听。动画不延迟卡片可用，不阻止继续提问或阅读；点击 Bot 可以打断完成动画并弹跳。
- 回答失败作为本轮一次信号触发短警报，文案保持显示；基础待机／倾听继续由焦点决定，警报结束恢复正常表情，焦点变化不重播。失败不阻止后续提问或待机轮换。
- 完成信号由 home 的唯一展示调度提供，Bot 按本轮 ID 消费一次并自行计时。清空、中止、未匹配与错误不庆祝；追问取消旧动作与粒子，导航返回不重播历史完成反馈。隐藏时丢弃临时反馈，换动作清理彩带及旋转速度记录。
- 待机轮换完整表情：平静 20～30 秒后，从开心／好奇／害羞／得意／俏皮五种表情中随机选择一次，保持约 2.5 秒，再回到平静。待机单独扩大表情池，其他交互场景仍最多两个候选。复用原引擎对应的眼睛、轻微歪头与身体姿态；同一时间只呈现一个表情，不新增连续身体花式动作。平静期间固定基础眼型，只保留轻微呼吸与眨眼，不独立轮换眼型，全部状态继续排除 7、8。
- 待机表情优先级最低；主题卡片悬停／聚焦、输入框聚焦、提问及其他场景即时接管。页面隐藏或启用减少动态效果时停止轮换；恢复后重新等待，不补播。移除自动嗡鸣及其避让规则，嗡鸣仅保留在开发预览。关闭鼠标位置跟随，切换动态效果偏好也不重新启用。
- 进入倾听时轻点头一次，目标动作持续约 550ms，随后保持固定的倾听眼型与视线，只保留轻微呼吸和眨眼。输入框持续聚焦或打字不会循环点头；重新进入倾听可再次回应，提交立即切换书写。点头使用引擎的状态经过时间，不添加业务计时器。
- 页面连续 60 秒没有鼠标移动、点击、键盘、触摸或滚轮操作后睡着，并持续闭眼呼吸，不自动恢复。睡眠可取代普通待机表情，输入框仅保持焦点时也可睡着；回答中不计时、不睡眠。活动时播放约 3 秒醒来，然后恢复待机／倾听；连续活动不重播醒来，提问和直接交互可即时接管。隐藏或离开首页取消睡眠与计时，返回重新计算。减少动态效果时静态闭眼，活动后直接恢复正常表情。
- 减少动态效果仍保留文字／卡片节奏，角色静止且不绘制粒子或彩带。四模块不变，不改 Answer 契约、不增加依赖；删除不再需要的 use-bot-gestures，完成事件与去重归 Bot 控制器。
- 验证完整待机表情的停留／恢复、交互抢占、隐藏与动态效果偏好切换，以及点击／键盘、书写→转身→单次跳跃→落地粒子→待机、真实粒子出现与清理、逐张可用卡片、取消旧调度、阅读返回与小屏。
- 待机计时和清理遵循 [React Effect 生命周期](https://react.dev/reference/react/useEffect)，动态偏好通过 [MediaQueryList change 事件](https://developer.mozilla.org/en-US/docs/Web/API/MediaQueryList/change_event)即时响应；配置、定时与优先级均留在 bot 内，不修改 home 的状态或对外接口。
- 自动睡眠复用现有引擎 sleeping／waking；场景允许持续到活动发生，动作优先级及取消仍由控制器处理。按 [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointermove_event)监听页面活动，按 [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)清理后台定时器；验证临界时间、计时重置、持续睡眠、单次唤醒、回答抢占、后台／卸载清理与桌面／触屏。
- 依据：[MDN 原生 click 事件](https://developer.mozilla.org/en-US/docs/Web/API/Element/click_event)覆盖鼠标、触摸与键盘激活；[React reducer 文档](https://react.dev/learn/extracting-state-logic-into-a-reducer)用于集中维护事件转换。完成反馈按用户最新要求替换嗡鸣：复用原引擎转身与粒子，在内部增加单次跳跃时序，不扩展业务接口。[MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)建议按时间推进动画，沿用引擎时间戳保证不同刷新率下顺序与时长一致。

## Bot 动作收敛（2026-09-22，历史记录）

用户试用后认为单次回答切换动作过多，并明确移除进度环。以下约定覆盖首轮的逐阶段动作编排：

- 每次提问只在书写／口述中选择一次，从提交持续到文字与全部卡片展示完成；提交、等待、文字和卡片阶段不重新选择动作。
- 展示完成立即回到待机或倾听，不再播放发送、进度、通知／开心串联，也不保留专为完成反馈添加的延迟。错误仍作为中止后的异常状态提示。
- 保留 Bot 的位置移动、现有文字分块与逐张卡片节奏、追问／清空取消和导航返回不重播。
- 从正式界面及开发预览移除进度选项和进度参数传递；其余 15 种预览保留，原始 vendor 动作库不作大规模裁剪。
- 职责不变：home 只向 Bot 提供当前是否在回答与本轮标识；Bot 内部选择并保持一个动作。React Effect 的依赖与其读取的状态一致，回答期间 mood 不随内容阶段变化。参考 [React 官方 Effect 依赖说明](https://react.dev/learn/removing-effect-dependencies)。
- 验证一轮从点击到全部卡片可用只出现一个输出动作、没有进度环；检查桌面／手机、连续追问、焦点、清空和减少动态效果。

- 文字输出结束后，完整卡片逐张出现，出现后立即可以点击；本轮不逐字段填充卡片。
- 角色基本外形保持 blob，问答流程固定；同一阶段可以随机选择合适动作，允许书写、环绕等短暂符号变形。随机选择发生在进入阶段时，不在每次渲染或播放中重新抽取。
- 仅排除用户提供的三张眼睛样本：[首页左偏眼型](assets/bot-eyes/excluded-home.png)、[工作示例眼型](assets/bot-eyes/excluded-working.png)、[生气示例眼型](assets/bot-eyes/excluded-angry.png)。其他眼型可以接受，不扩大为统一眼型、禁止所有不对称表情或删除整个工作／生气状态。三张样本不预设对应三个不同的底层预设。
- 既有预写问答、四模块职责、会话保留与阅读返回约定继续作为基线。本轮不新增语音、上传、实际拖拽、点击彩蛋或自动休眠。

### 首轮实现与验收

- 输入：最新预写回答、输入焦点、请求状态与已显示卡片数量；输出：分块文字、逐张完整卡片和同步 Bot 表现。问题立即出现，提交反馈与已有位置过渡同时进行。
- 固定流程为提交反馈 → 分块输出 → 逐张卡片 → 短暂完成反馈 → 待机／倾听。真实请求尚未返回时才增加等待阶段；无卡片时跳过卡片阶段。提交约 1 秒，典型文本约 2.6 秒起，卡片间隔约 300 毫秒，完成反馈约 650 毫秒，作为首轮试播参数。
- 表现候选：提交使用发送；等待在加载／思考／环绕中选择；输出在书写／口述中选择；卡片展示使用实际数量进度；完成在通知／开心中选择。阶段优先于输入焦点，结束后恢复倾听或待机。完成反馈不延迟卡片可点击时间。
- 展示进度由 home 中唯一的展示调度管理，文字、卡片和 Bot 共享同一阶段。Bot 内部选择动作并管理引擎，useConversation 继续只管理消息与请求；不改变 Answer 数据契约。
- 追问立即补全旧回答和卡片，只有最新回答播放；清空、卸载取消旧调度；导航返回不重播。换主题不重建引擎，减少动态效果保留文本与卡片出现节奏并停止装饰运动。
- 添加仅开发环境可访问的动作预览，支持 16 种候选动作、大小与进度检查，完整场景使用真实首页视图试播；生产环境不提供该入口。
- 核实三张排除样本对应眼型 7、8，只从所有状态的眼型播放清单中排除它们，保留其他眼型及状态。检查状态切换过程。
- 验证：调度与随机选择的模块测试；端到端验证阶段顺序、分块、逐张卡片、进度同步、快速追问、清空、阅读返回、明暗主题和减少动态效果；浏览器试播大尺寸和会话小尺寸，并完成现有检查。

### 已核实的实现事实

- 引擎支持运行时切换状态和单次动作；本轮改造前的 React 入口只接入 idle / listening / thinking / happy。
- 原引擎待机的眼睛预设 0 / 8 每隔 9～16 秒轮换；预设 8 在没有跟随偏移时也出现首页样本中的左偏与倾斜差异。逐一预览 25 个眼型确认另两张样本均对应预设 7。
- 原进度动画是循环视觉效果；首轮适配后可接收已展示卡片的实际进度。上传、口述、拖拽等状态本身不提供对应业务能力。

## 问答扩展边界

页面只依赖一个异步回答函数：接收本次问题与可选的明确主题，返回精简回答和相关项目、笔记等内容引用，由页面将每个内容条目呈现为独立卡片，并指向其外部项目地址或站内正文。第一版由本地预写内容实现；未来接入 AI 时可替换回答实现，不需要把页面展示逻辑绑定到某个模型。当前不增加 provider 框架、远程调用、数据库、配额或限流系统，也不预设流式响应与会话持久化契约。

## 已确认技术栈

- Next.js App Router + React + TypeScript：组织主页、后续文章页面及交互组件，部署到 Vercel。
- Tailwind CSS + shadcn/ui：优先用工具类和可直接修改的组件源码构建页面；保留少量用于主题与特殊动画的 CSS，不套用组件库的默认整页外观。
- Lucide + Geist：沿用原型图标体系和字体。
- Bot 的现有引擎在模块顶层访问 `window`，若采用 Next.js，需要隔离为仅在浏览器加载的组件；不能只靠 `'use client'` 处理该依赖。
- 第一版问答使用本地预写内容，经单一回答接口提供给页面；不预先引入模型接口或后台内容系统。

官方依据：[shadcn/ui](https://ui.shadcn.com/docs)、[Next.js CSS](https://nextjs.org/docs/app/getting-started/css)、[Next.js on Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs)、[Next.js 客户端加载](https://nextjs.org/docs/app/guides/lazy-loading#skipping-ssr)。

### Next.js 的选型依据

当前单页原型用 React + Vite 即可实现，使用 shadcn/ui、部署 Vercel 或未来接入 AI 均不强制依赖 Next.js。Next.js 的主要价值在于内置页面路由、共享布局和 HTML 预生成，适合未来有独立 URL 的站内文章；代价是需要处理服务端与客户端组件的边界。普通 Vite React SPA 更直接，但默认不会提前生成文章正文 HTML，如需预渲染则要补充相应工具。

Next.js 可静态生成页面，不等于每次访问都需要服务端渲染。React + Vite 未来也可以在同一 Vercel 项目中加入 `/api` 服务端函数调用模型，无需另建常驻服务器。因此，应先结合整体页面结构决定框架，不因尚未确定的 AI 功能引入后端。

核查来源：[Next.js 页面与布局](https://nextjs.org/docs/app/getting-started/layouts-and-pages)、[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)、[Vite 预渲染](https://vite.dev/guide/ssr#pre-rendering-ssg)、[Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite)、[Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js#create-a-node.js-function-in-api)。
