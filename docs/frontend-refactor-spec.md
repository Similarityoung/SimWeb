## Bot 移动动画（2026-09-21）

- 输入：首次点击首页主题卡片或提交问题，使首页进入会话状态；目标为现有会话顶部名字左侧的 assistant 头像位置。
- 行为：同一个 Bot 连续移动并等比缩小，过渡约 560ms；清空会话时反向返回。后续追问不重复移动，回答不等待动画完成。
- 边界：桌面和手机根据实际布局测量；减少动态效果时立即切换；过渡中清空可连续转向；离开页面正常卸载，返回已有会话时直接显示头像。
- 实现：仅在首页 Introduction 的 Bot 外层使用 Motion 布局动画，保持角色 SVG、引擎实例和回答契约不变。不将动画状态放入 useConversation。
- 验证：记录浏览器中的移动中间帧、头像尺寸和 SVG 连续性，验证正向、返回、减少动态效果以及既有阅读流程；桌面和手机均执行。

## 回答分块输出（2026-09-21）

- 输入：首页主题卡片或输入框生成的现有预写回答；不接入真实模型。
- 输出：将新回答模拟为大小不一、间隔变化的文本块，每块到达时整块追加；不匀速逐字播放。短回答通常在约一秒内完成，随后展示关联内容卡片。输出时显示静态小圆点，Bot 的位置过渡与文字输出同时进行。
- 边界：快速追问时补全旧回答，只输出最新回答；清空或离开首页时停止定时器；从目录或正文返回时历史回答立即完整显示。按用户要求，减少动态效果时仍保留分块输出，只停用装饰过渡。辅助技术读取完整文本，不逐块播报。
- 依赖：新增 home 内的 AnswerContent 展示组件及局部分块函数，首页只记录挂载时已有的消息 ID；不修改 Message / Answer 契约、回答函数、会话 Hook 或 Bot 引擎，不增加依赖。
- 验证：桌面和手机检查文本整块追加、内容卡片在完成后出现、快速追问与清空、阅读返回不重播，以及减少动态效果时仍输出文本块。
- 依据：[DeepSeek 流式响应文档](https://api-docs.deepseek.com/api/create-chat-completion/)中的 SSE `delta.content` 增量与 `[DONE]` 结束标记。这里只模拟接收效果，分块大小和间隔不是模型 tokenizer 或真实 API 测量数据。

### Next.js 的选型依据

当前单页原型用 React + Vite 即可实现，使用 shadcn/ui、部署 Vercel 或未来接入 AI 均不强制依赖 Next.js。Next.js 的主要价值在于内置页面路由、共享布局和 HTML 预生成，适合未来有独立 URL 的站内文章；代价是需要处理服务端与客户端组件的边界。普通 Vite React SPA 更直接，但默认不会提前生成文章正文 HTML，如需预渲染则要补充相应工具。

Next.js 可静态生成页面，不等于每次访问都需要服务端渲染。React + Vite 未来也可以在同一 Vercel 项目中加入 `/api` 服务端函数调用模型，无需另建常驻服务器。因此，应先结合整体页面结构决定框架，不因尚未确定的 AI 功能引入后端。

核查来源：[Next.js 页面与布局](https://nextjs.org/docs/app/getting-started/layouts-and-pages)、[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)、[Vite 预渲染](https://vite.dev/guide/ssr#pre-rendering-ssg)、[Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite)、[Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js#create-a-node.js-function-in-api)。
